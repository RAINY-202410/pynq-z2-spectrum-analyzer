# 技能包

本目录不是比赛题目的使用说明，而是可迁移到其他 AMD/PYNQ 项目的经验包。
每个技能均说明适用范围、使用方法、失效条件和已验证效果。

## 技能列表

### `pynq_overlay_dma_bringup`

面向 PYNQ Overlay、AXI DMA、AXI-Stream、I2S/codec 和多硬件模式共存问题。
它与当前频谱分析算法解耦，换题目或换 PYNQ 板卡时仍可复用。

已验证效果：

- 定位并验证 M4 双声道采集的 I2C、MCLK、I2S、DMA 数据通路；
- 将 FFT LIVE 与 M4 采集改为同进程互斥模式；
- 在主机测试中验证鉴权、模式切换、状态恢复和失败拒绝路径。

### `fpga_delivery_audit`

面向 FPGA 竞赛工程交付前的目录、命名、源码、bit/hwh、报告、manifest
和压缩包一致性检查。适用于 Vivado、PYNQ 或纯 RTL 项目。

已验证效果：

- 发现源码修改后未重建 manifest、旧 ZIP 未覆盖等问题；
- 把“主机通过”和“板端通过”分开记录，阻止误写 `board_accepted=true`；
- 对最终目录执行英文小写命名和逐文件 SHA256 校验。

## 使用顺序

1. 硬件/驱动阶段使用 `pynq_overlay_dma_bringup`；
2. 报告与提交阶段使用 `fpga_delivery_audit`；
3. 将新失败案例补入对应技能的“失效条件”，不要只保存成功日志。

## 设计原则

- 每个结论必须绑定来源文件、哈希或实测样本；
- 先冻结数据格式和黄金模型，再连接实时硬件；
- 同一进程只允许一个硬件拥有者；
- 主机测试、板端冒烟、长测和最终验收分别命名；
- 找不到原始报告时明确写“缺失”，不从 bitstream 猜资源数字。
