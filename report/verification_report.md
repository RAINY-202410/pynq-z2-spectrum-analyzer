## 2. FFT 数值与协议

- 每帧输入 1024 点，输出 1024 个 complex uint64；
- 12 个主例覆盖 zero、DC、impulse、单 bin 和双 bin；
- 覆盖矩形窗和 Hann 窗；
- ABORT 后可重新配置、重新启动并恢复输出；
- 所有 1024 个复数点与冻结参考逐整数一致；
- 协议回归检查 TLAST、TKEEP、busy、AXI-Lite 握手和错误事件。

限制：故障注入覆盖引擎输入溢出和显式 FFT 事件检测，不代表已覆盖所有
数值 FFT 内部溢出组合。

## 3. 基础频谱板端验证

- R2 长测：1820.013160629 秒，9100 帧；
- 连续前台可见时间：1819.799418538 秒；
- 长测后恢复：20.031739564 秒，100 帧；
- R3 短复验：4 次、321 帧；
- R3 三次实际冷启动：三次 boot id 和服务实例均不同；
- 每次冷启动约 20.0 秒、100 帧并安全停止；
- 实测 `fs` 约 47998.39 Hz。

保留限制：r2 长测不能标成 r3 长测；CMA 长时变化来源仍未完全归因。

## 4. CPU FFT 对照

PC 与 PYNQ ARM 使用相同 12 类输入，每类预热后采集 20 批 × 500 次：

- ARM 批均值范围：`351.8725～372.8343 µs`；
- PC 批均值范围：`8.9850～9.2766 µs`。

该结果是 NumPy 1024 点 FFT 的 PS 微基准，包含 Python 调用和输出分配，
不包含 ADC/DMA/绘图，因此不用于计算 PL 加速比。

## 5. B-X11 直通校准

条件：

- 信号源 OWON XDG3122；
- 实际输出 `0.2 Vpp`；
- 温度 `26 °C`；
- 16 个设计频点，每点 3 个校准块 + 3 个验证块；
- 6 kHz 补采块按用户要求排除。

结果：

- 16/16 点通过；
- 验证与校准平均增益最大绝对差：`0.0002139 dB`；
- 验证与校准平均相位最大绝对差：`0.0018429°`；
- 实测 `fs=47998.779988 Hz`。

## 6. B-X12 RC 测量

条件：

- 实际 `R=978 Ω`；
- 实际 `C=105.6 nF`；
- 温度 `25 °C`；
- 左声道 `input_reference`，右声道 `rc_output`；
- 每个频点 3 个校准块和 3 个独立验证块。

结果：

- 16/16 点 `RC_PASS`；
- 理论截止频率：`1541.052 Hz`；
- 一阶复数拟合截止频率：`1547.745 Hz`；
- 相对偏差：`+0.4343%`；
- 最大验证重复性差异：`0.000391 dB` / `0.002716°`；
- 相对理论最大误差：`0.4194 dB` / `1.0548°`。
